望楼

wanglou · read-only server monitor

一个只看不碰的服务器监控。探针只往外发数据，没有任何入口能让面板在你的机器上执行命令。面板被攻破，最坏结果是监控数据泄露；某台 VPS 被攻破，影响停在那一台。

三条原则

安全来自没有那个功能

单向数据流

探针只出不进

agent 主动发起 HTTPS 上报，不开端口、不保持可被利用的长连接下行指令。服务端的响应只有 204 或 4xx，agent 不解析任何响应体。

每节点独立密钥

拿到一把钥匙只能开一扇门

每台机器本地生成 Ed25519 密钥对，私钥不离开本机。服务端只存公钥。泄露一台的私钥，只能伪造这一台的数据。

最小权限

探针不需要 root

CPU、内存、磁盘、网络都能从 /proc 和 statfs 读到。agent 以专用无权限用户运行，systemd 沙箱锁死文件系统和能力集。

爆炸半径对比

同一次入侵，两种架构的后果

切换架构，然后点“攻破面板”或直接点任意一台机器模拟它被入侵。哪吒式指带 Web 终端、远程命令和计划任务下发的监控面板。

架构

三个进程，一个方向

接收端和面板可以是同一个二进制的两个端口。推荐把面板放在 Cloudflare Access、Tailscale 或 Basic Auth 后面，接收端单独暴露。

四种入侵场景

刻意不做的功能

砍掉的东西，就是被拿走的攻击面

这些功能需要面板到 agent 的下行通道。需要时请用 SSH、Ansible 等独立鉴权的工具。

Web 终端

等于把 root shell 挂在网页上。用 SSH + 密钥 + fail2ban。

远程命令 / 计划任务

批量执行是攻击者最想要的能力。用 Ansible 从你的本地机器发起。

文件管理

任意读写需要高权限。agent 只读 /proc，碰不到你的文件。

面板触发的自动更新

更新走系统包管理器，由离线密钥签名，不受面板控制。

agent 端配置下发

上报间隔等配置写在本机 /etc/wanglou/agent.toml，只有 root 可改。

内网穿透 / 端口转发

与监控无关，且会让 agent 变成跳板。

私钥存放于 /etc/wanglou/node.key，属主 wanglou，权限 0400。agent 被杀或失联超过 3 个周期，服务端告警。

接入一台新机器

私钥从不经过网络

  1. 在 VPS 上安装并生成密钥

    wanglou-agent init --name hk-01 在本机生成 Ed25519 密钥对，打印公钥指纹。

  2. 在面板登记公钥

    粘贴公钥，或使用 10 分钟有效、只能用一次的注册码让 agent 提交公钥。注册码只能登记公钥，不能做任何其他事。

  3. 核对指纹后启用

    面板显示指纹，与第 1 步输出一致才点启用。之后该节点只接受这把公钥签名的数据。

  4. 吊销

    机器疑似被入侵时在面板吊销其公钥，该节点数据立即被拒收，其他节点不受影响。

技术选型与路线

从能用到好用

M1 · 能跑

  • Go 写 agent，CGO 关闭，静态编译 amd64 / arm64
  • 服务端 Go + SQLite，前端静态文件嵌入二进制
  • Ed25519 验签、防重放、失联告警、Telegram 推送

M2 · 好用

  • SSH 登录告警、二进制哈希告警
  • 1 分钟 / 1 小时降采样，默认保留 90 天
  • 公开状态页（可选，脱敏 IP）

M3 · 更稳

  • 双接收端：agent 同时上报两个地址，一个被拿下仍有告警
  • 外部心跳：接收端定时 ping Healthchecks 类服务，面板挂了也会知道
  • apt / rpm 签名仓库
望楼 · 设计方案草稿。威胁模型中关于哪吒的描述基于其公开功能（Web 终端、命令下发、计划任务、自动更新），具体风险取决于部署配置。
